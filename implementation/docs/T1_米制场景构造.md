# T1 米制场景构造：工具接口

机器定义：`schemas/T1.schema.json`。请求/响应类型分别见 `definitions/request`、`definitions/success_response`、`definitions/error_response`。

## 职责与当前支持范围

把基座模型的环境假设整理为统一米制场景。当前参考实现只接收**已位于本轮参考时刻、自车中心坐标系下的轴对齐米制假设**，执行校验、来源检查与标准化复制；不声称已经实现图像到米制投影、异时动态对齐或一般几何融合。

不支持的投影或坐标系不得被“自动猜测”。模型与适配器须先提供满足当前剖面的数据，否则报错。后续坐标变换功能应有单独实现与测试，并升级相应剖面定义。

## 输入：payload

| 字段 | 提供方 | 说明 |
|---|---|---|
| `metadata` | 可信调用端 | 场景版本、来源、参考时刻、坐标与网格 |
| `observations[]` | 采集端 | 图像编号、采集时间与图像引用；本工具不读取像素 |
| `ego` | 自车状态采集端 | 自车中心初态，当前位置和航向为零 |
| `vehicle` | 车辆配置 | 前后尺寸、半宽及运动边界 |
| `decision` | 驾驶智能体 | 同一版本的驾驶决策；不能由 T1 修改 |
| `model_hypotheses` | 基座模型/其结构化适配器 | 道路边界、目标状态、未来区间占用、未知区域、图像证据 |

`model_hypotheses.observed_at_s` 必须等于参考时刻。目标未来占用必须完整覆盖预测网格，每段表达整个时间区间内的覆盖包络；不能仅提供孤立时刻位置。单位、时间约定及字段明细见共享格式说明。

## 输出：payload.scene

输出根场景对象，保留 metadata、图像证据、目标位置与速度、占用和不确定性。`valid_until_s` 等于参考时刻加规划窗口。T1 不增加目标、不估计未提供的速度、不根据速度外推占用、不修订驾驶意图。

## 处理顺序

1. 严格 Schema 校验；拒绝 NaN、无穷数与额外字段。
2. 校验参考时刻、图像时间窗口、证据引用及编号唯一性。
3. 校验矩形合法性、完整预测覆盖，以及当前位置与首区间占用一致性。
4. 校验车辆初态与当前实现剖面、决策版本、有效期限和让行对象引用。
5. 产生米制场景，输出前再校验响应 Schema。

## 主要错误

| 错误码 | 含义 / 智能体或调用端应做的事 |
|---|---|
| `SCHEMA_ERROR` | 字段、类型、坐标剖面不符合契约；修正结构化输出 |
| `NONFINITE_NUMBER` | 数值无效；不能用无穷值表示未知 |
| `MISSING_EVIDENCE` | 证据图像不存在；补全或修正引用 |
| `HYPOTHESIS_TIME_MISMATCH` | 模型假设不属于本轮观测时刻；重新输出对齐假设 |
| `OCCUPANCY_COVERAGE_GAP` | 占用覆盖有空缺、乱序或网格不符；补足假设 |
| `HYPOTHESIS_INCONSISTENT` | 当前目标位置与首段占用冲突；重新检查场景 |
| `UNSUPPORTED_INITIAL_POSE` | 当前工具不支持该参考点/运动剖面 |
| `SCENE_VERSION_MISMATCH` / `DECISION_EXPIRED` | 决策串轮或过期；重新决策 |
| `SYNTHETIC_INPUT_DISABLED` | 人工输入未显式启用测试模式 |

## 示例与验收

- 完整请求：`examples/pedestrian_crossing.request.json`。
- 完整响应：`results/normal.trace.json` 的第二条消息。
- 根场景：`results/shared_scene.example.json`。
- 验收：正常输入通过；缺一段占用、未知图像引用、时间不匹配、重复编号、非法数值和错误版本均须显式拒绝。通过只说明结构自洽，不代表 G2 已通过。
