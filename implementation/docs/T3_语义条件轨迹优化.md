# T3 语义条件轨迹优化：工具接口

机器定义：`schemas/T3.schema.json`。语义行为由驾驶智能体指定；本工具只在该行为约束内寻找运动轨迹。

## 输入与输出

输入 `payload` 必须包含 `scene`、`decision`、`corridor`，其场景版本和时空约定一致。

输出 `payload.trajectory`：

| 字段 | 定义 |
|---|---|
| `metadata` | 原场景元数据 |
| `points[]` | 按共享时间网格排列的轨迹点，包含两个端点 |
| `points[].time_s` | 相对参考时刻，秒 |
| `x_m,y_m,yaw_rad` | 自车中心位置与航向，米/弧度 |
| `speed_mps` | 非负前进速度，米/秒 |
| `acceleration_mps2` | 从该点到下一点的恒定纵向加速度，米/秒²；末点值用于完整记录，不代表额外执行段 |
| `curvature_per_m` | 曲率，当前剖面固定为零 |
| `solver` | 求解器名称、候选数、目标函数值；不能把返回成功解释成全局最优 |
| `requested_prefix_s` | 请求执行的前缀长度；最终由 T4 决定释放量 |

## 已实现的参考求解器

当前是**可审计的纵向候选枚举**，不是尚未实现的 CasADi/IPOPT 非线性优化器。

- 停车让行候选加速度：0、−0.5、−1、−1.5、−2、−2.5、−3 米/秒²。
- 直道起步候选加速度：0、0.5、1、1.5、2 米/秒²；达到期望速度后保持该速度。
- 剔除超出车辆加减速边界、速度边界、停车截止时刻或停车位置的候选。
- 控制切换需落在共享时间网格上；否则该候选不参与求解，避免恒加速度字段与采样轨迹不一致。
- 用候选参考点在整段时间内的扫掠范围检查走廊包含关系，而不是只检查一个端点。
- 在剩余候选中最小化：速度偏差代价与加速度平方代价的时间累积；示例权重为 0.05 和 1。

每段采用恒加速度直线解析积分。停止后不允许继续用负加速度造成倒车。恢复行驶案例重新使用新的自车坐标和参考时刻，不拼接旧坐标。

## 硬约束与偏好

**硬约束**：走廊、停车上界与截止时刻、车道指定、速度/加速度边界，以及当前参考实现的直道运动关系。

**偏好**：接近期望速度、减小控制强度。期望速度是软目标；初版起步轨迹不保证在窗口结束时恰好达到期望速度。

本实现不处理转向、曲率变化、jerk 或跟车间距规则；这些不能靠字段预留冒充已经完成。`max_curvature_per_m` 为后续扩展配置，当前所有候选曲率均为零。

## 失败与验收

- `NO_FEASIBLE_TRAJECTORY`：本候选集合内没有可行轨迹，不能声称证明了一般最优控制问题无解。
- `UNSUPPORTED_LATERAL_MOTION`：当前求解器不能满足给定横向目标。
- `UNSUPPORTED_BEHAVIOR`：尚未实现的行为模板，例如 `hold_lane`。
- `CORRIDOR_COVERAGE_GAP`、`SCENE_VERSION_MISMATCH` 等公共错误：输入串轮或时间网格不完整。

正常停车示例在前进 12 米处停车；智能体把上界改为 10 米后，在 9 米处停车；这些数值是当前人工测试的预期输出，不是通用求解保证。

请求/响应见 `results/normal.trace.json` 第五/六条消息。验收要求：正常停车与起步通过；制动能力不足时显式返回候选无解，不改变驾驶行为；轨迹能被独立核验器接受。
