# T2 时空走廊构建：工具接口

机器定义：`schemas/T2.schema.json`。本工具不调用目标预测模型，不在停车让行失败后自行改为绕行或超车。

## 输入与输出

| 方向 | 字段 | 含义 |
|---|---|---|
| 输入 | `scene` | T1 输出的统一米制场景 |
| 输入 | `decision` | 同版本驾驶行为、车道区域、停车要求 |
| 输入 | `safety_margin_m` | 可信实验配置提供的最低间距，示例为 1 米；不能由模型置信度随意降低 |
| 输出 | `corridor.metadata` | 原样继承场景版本、时空网格与来源 |
| 输出 | `corridor.safety_margin_m` | 本轮核验必须继承的间距配置 |
| 输出 | `corridor.cells[]` | 每个时间区间的 `start_s/end_s/allowed_rectangles[]` |

`allowed_rectangles` 描述的是**自车中心允许出现的区域**，已计入车身尺寸。多个矩形表示一个区域并集；T3 不得把它们简单合并成更大的外接矩形，从而跨越中间障碍。

## 构造算法

1. 将模型道路矩形按道路不确定性、车辆前后长度和半宽内缩，得到自车中心可行域。
2. 与驾驶决策指定的横向车道范围相交。停车让行时再施加自车中心不得越过停车上界；恢复行驶时不沿用停车上界。
3. 对每个目标、每个时间区间，从模型原始占用开始，先加位置不确定性和安全间距，再转换为自车中心的禁止区域。
4. 禁止区域横向扩大自车半宽，纵向下界减去自车前部长度、上界加上后部长度；由此支持前后尺寸不同的车辆。
5. 将未知区域同样视为禁止区域，从允许域中逐次做矩形差集，保留全部分块。
6. 检查每段非空、初态可容纳、相邻区间有连续衔接区域。输出走廊。

车辆尺寸只在本次自车中心空间转换中应用一次。场景中的模型目标占用不是“已包含自车尺寸的障碍”，不得重复传入膨胀后的结果。T4 使用原始场景另行核验，不是再把 T2 的禁止区域膨胀一次。

相邻区间有几何重叠只是连续性必要检查，不证明满足车辆动力学；后者交给 T3 和 T4。矩形包络与矩形差集可能较保守，但不会因此引入未提供的环境信息。

## 错误与验收

| 错误码 | 含义 |
|---|---|
| `CORRIDOR_EMPTY` | 道路、车身、未知区域或障碍导致某时段没有允许区域 |
| `INITIAL_STATE_BLOCKED` | 当前自车状态不在首段允许区域内 |
| `CORRIDOR_DISCONNECTED` | 相邻区间无法连续衔接 |
| `INVALID_GEOMETRY` | 某矩形边界无效 |
| 公共错误 | 时空版本、占用覆盖、有效期限或数据结构错误 |

错误中提供区间起始时刻，或导致空域的约束描述。智能体需据此补充场景或修订决策；T2 不输出替代驾驶行为。

示例：`results/normal.trace.json` 第三/四条消息分别为请求/响应。验收包括正常车道、未知区域全阻塞、初态被占据，以及版本不一致；车身前后不对称也应正确转换。
