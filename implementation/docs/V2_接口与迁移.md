# V1.0 研究实现的 v2 剖面接口与迁移

软件名称仍为 Agentic Semantic-to-Physical Driving V1.0。新增数据契约 `schema_version=2.0.0`、`profile=convex_disk_bicycle_v2`。旧 `1.0.0` JSON、四份旧工具 Schema、`driving_tools.py` 和纵向枚举不改变字段意义；旧接口不能接收新场景。v2 入口是 `agentic.tools.call_tool`，四个实现分别为 `agentic/t1.py` 至 `t4.py`。

## 来源与单位

采集输入由可信调用端提供，严格机器定义在 `capture_v2.schema.json`。`reference_time_s/capture_time_s/valid_until_s` 是同一采集时钟的绝对秒数；可另存原始 `capture_utc`，没有则为 null。预测区间与轨迹 `time_s`、停车 deadline 是相对秒。模型只返回采集 time_id，不能写入可靠时间戳。参考时刻必须对应实际帧；历史默认 2 秒、预测 5 秒、步长 0.2 秒，均通过 capture 配置。多相机同一时刻可共用 time_id，冲突时间拒绝。每轮场景 ID、revision、完整 metadata 和场景内容 SHA256 绑定所有产物。

坐标 x 向前、y 向左、z 向上，原点在参考时刻自车中心，该时刻自车位置/航向必须归零（速度来自实测），距离 m、航向 rad、速度 m/s、加速度 m/s²、曲率 1/m。模型目标状态必须在参考时刻，关联当前帧证据；工具不根据自车运动推断动态目标的异时状态。导航只是一段意图文字，无地图接口。

在线适配器填写 `source=online_model`、请求/响应模型 ID、图像 SHA256、输出 SHA256、提示词版本和哈希、调用次数。人工替身填写 `source=synthetic_fixture` 且须显式 allow_synthetic。来源标签是可信调用端记录，不是密码学来源证明；离线读入的来源记录需由实验负责人保管核查。工具无法凭一段 JSON 证明曾发生真实调用。

## 模型契约

`agent_output_v2.schema.json` 全部字段必填，禁止未知字段。decision 包含行为、目标中心区域、速度偏好、让行对象、停车要求、优先级、有效期、硬要求和代价权重。优先级用于记录智能体意图，不授权工具修改行为。当前行为模板：stop_yield 必须有停止中心 x 上界及 deadline，并在其后保持速度零；hold_lane/resume 只在目标区域内前进，stop 必须为 null。道路、碰撞、车辆运动界限、区域、停车和让行为硬约束；速度、加速度、转向和平顺性代价为偏好。交通证据当前仅支持 stop_required/yield_required、active/inactive/null：active 要求停车让行，yield_required 还需对象引用；null 或其他规则显式拒绝。T4 从原始证据重新检查一致性。无变道/超车/交通信号通用规则解释器；模型须把有证据的规则落实到受支持行为，未支持的规则不得据此声称完成核验。

hypotheses 包含道路多边形、目标位置/速度、各区间整个目标车身占用的多个可能多边形、交通证据、未知区域、证据 frame_ids/time_ids、尺度依据和不确定性。未知位置/速度为 null；有完整占用时可保留未知瞬时速度。未知道路、未知占用覆盖或无界未知区域会阻止规划。位置与道路 uncertainty 为条件式膨胀假设；null 会拒绝规划，自报 confidence_note 绝不转换成概率或已校准误差界。不能提供占用的模型响应会被拒绝，不能用点预测声称连续时间安全。

T1 保留每个备选占用，检查时间、单位、证据、几何、初始占用冲突、版本和有效期，不进行平均融合。当前仅接受模型给出的原生米制场景。`geometry.project_ground` 提供显式标定、刚体相机姿态、静态地面接触点的射线求交辅助函数；不会自动用于动态目标或无标定图像。不支持的图像坐标/外部坐标由 Schema 拒绝，不会从单目图像虚构尺度；`model_metric_hypothesis` 仅为模型假设，真实性需 G2 测量。`calibrated_ground_plane` 标签本身也不是校验证明，调用端须保管相应标定/前提；当前在线格式不传标定，建议只使用 model_metric_hypothesis 或 unknown。

## 四工具 JSON 调用

请求：`{"kind":"request","tool":"T1","request_id":"r1","payload":{...}}`。

| 工具 | payload | 成功 payload | 定义 |
|---|---|---|---|
| T1 | capture, output, provenance | scene | capture_v2 / agent_output_v2 / scene_v2 Schema |
| T2 | scene | corridor | corridor_v2 Schema |
| T3 | scene, corridor | trajectory | trajectory_v2 Schema |
| T4 | scene, trajectory | verification | 下述核验结果；不读取 T2 的安全界限 |

成功响应 `kind=response,status=ok,payload=...`；错误 `status=error,error={category,code,message,details,repair_request}`。category 区分 interface_error 与 tool_infeasible；T4 的轨迹不通过仍为成功工具调用，verdict=FAIL、released_prefix_s=0。不能把优化失败或接口错误当作核验通过。

T2 输入 margin/prefix 取自场景中可信 safety 配置。原始目标 BODY 占用仅加一次目标 uncertainty、安全间距和自车包络；输出是后轴参考点的配置空间。车身使用以后轴为圆心、半径 `hypot(max(front+d,abs(rear-d)),half_width)` 的外接圆。道路内缩该半径及道路不确定性，目标中心区域按 d 保守内缩。障碍每种备选先取凸包，再用当前后轴到凸包最近点确定固定分离半平面；所有备选约束取交。未知区域同样阻塞。每个凸走廊包含初始后轴，故相邻时段连通；不代表动力学可行。这个策略不会自行绕行，但可能拒绝一个实际可行的窄路/复杂绕障场景，拒绝会返回具体区间/目标。它不是完整的自由空间分解或通用路径搜索器。

T3 为实际 CasADi/IPOPT 多重射击约束优化，状态 x/y/yaw/speed 在后轴，控制加速度及前轮转角。中心位置由后轴沿航向加 d 恢复。区间内恒加速度、恒后轴曲率，路程 s=v*dt+a*dt²/2，圆弧用 sinc 解析积分，零转向使用稳定级数。完整轨迹输出中心/后轴位置、航向、速度、加速度、曲率、转角和求解器状态。每个走廊半平面在两端施加额外 s/2 裕量：圆弧任一点到最近端点的路径长不大于 s/2，因此覆盖整段运动而非只检采样点。停车 deadline 落在采样间时，施加该时刻及后续端点速度零；不通过负速度再恢复来绕过要求。硬约束不松弛。失败只表示本保守非凸问题的本次局部求解未成功，不证明全局无解。没有转向速率/jerk 硬限制或轮胎动力学；平顺性仅为代价。

T4 校验严格轨迹结构、完整时间网格、初态、版本、坐标/参考点、控制与曲率、速度/加速度/转角界限，再独立解析积分检查动力学。道路、目标区域、停车位置、deadline 及目标/未知区域碰撞全部从原始 scene 重建，不相信求解器标签或走廊。每段细分至不大于 0.02 秒，以解析状态和每小段路程/2 的附加几何界限包住采样间运动；细分本身不是安全依据。车身外接圆保守包住任意朝向的矩形；碰撞距离用原始占用多边形与后轴线段距离减外接圆半径、位置 uncertainty 及运动界限。碰撞会保守拒绝，有效性取决于模型整区间占用确实覆盖真实环境。

违例包含 code、object_id、time_interval_s、position_m、computed、threshold、unit、repair_request。核验结果含场景绑定、trajectory_digest、PASS/FAIL、violations、最小间距下界、检查时域、释放前缀及条件式 claim。允许的前缀不超过一个配置步长且不超过 0.5 秒。该结果不是车辆安全认证。

## 闭环与执行

每轮无条件调用驾驶智能体。失败的具体工具错误/违例反馈给智能体，revision 递增，有限修订后仍失败则不执行。通过时只释放短前缀。模拟器只解析积分自车公开状态，不包含道路/目标隐藏真值；执行结果不会给模型增加环境事实。新采集输入重新调用模型、T1–T4，旧许可不能复用。相同许可只能消费一次，轨迹更改、采集时钟变化或新观测会拒绝旧许可。此进程内接口不是分布式车辆控制/防伪服务。

离线 replay 对每个配对的采集文件和已记录模型输出重新运行四工具。它不会假装重新调用模型；要进行含失败修订的每轮在线闭环，可用 `ClosedLoop(OnlineAgent(), RunLog(...)).round(capture)`；持续观测源应逐轮调用 round。当前没有相机采集驱动或真实车辆控制器。

## 从 v1 迁移

没有自动无损迁移：旧数据没有后轴/轴距/转角界限、完整语义字段、time_id、来源图像哈希以及多边形区间占用。调用者显式提供车辆几何及新字段；矩形可按四角转成多边形，旧时间按采集记录分配 ID，仍须保留人工来源。不能把旧枚举轨迹标成自行车优化输出，不能把 fixture:// 改名成真实图像。旧 25 项测试继续运行，另有 v2 兼容/拒绝及工程测试。
