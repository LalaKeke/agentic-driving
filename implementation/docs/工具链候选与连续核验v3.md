# 工具链候选与连续核验 v3

本改动使用显式 `bounded_seed_candidates_v3`，只改善自车候选发现和独立核验的几何分辨率。原模型输出、道路、全部目标BODY及情景、模型残差、车辆限制和1米障碍间距不变。下述证据来自既有真实JSON的离线诊断，不是新的在线成功率，也没有据此认定已消费前缀。

## 两个实际问题

**固定转角使转向候选过早失效。** 原3个转向种子持续使用固定转角，在约8m/s初速下，常在0.6–0.8秒越过全局±0.35rad航向界，被T2拒绝。剩下original和brake_straight两条候选的航向带基本只有±0.025rad。对非负速度，这意味着后轴必须满足：

```text
abs(y − y0) ≤ tan(0.025) × (rear_x − rear_x0)
```

例如既有following/frame036的某条走廊在0.6秒要求右移至少0.18721m，但相邻格X上界与上述航向范围只允许最多0.14625m。当前走廊输入本身不相容，不能靠提高IPOPT迭代上限解决；这也不证明原场景所有轨迹都无解。

**粗连续包络可能保守拒绝临界轨迹。** 既有following/frame010的一条离线求解轨迹在原0.02秒核验子段上被TARGET_INTENT拒绝：起始后边界允许0.05m，而保守中心包络计算到0.089764m。同一轨迹使用更细子段后可以获得整区间证明。这里需要改善保守核验精度，不能移动模型道路或降低安全间距。

诊断脚本及见证暂存于 `../results/hard_clip_optimization_20261030_v1/diagnosis/hard_seed_diag.json`、`../results/hard_clip_optimization_20261030_v1/diagnosis/hard_corridor_reachability.json`、`../results/hard_clip_optimization_20261030_v1/diagnosis/hard_extra_diag.json` 和 `/tmp/hard_refined_witness_*.json`。它们是开发诊断材料；单独T4通过不能当作完整链路、独立接受器或模拟消费通过。

## 五个固定候选：只改变3条转向参考

见 [t2.py](../agentic/t2.py) 的 `candidate_seed_v3`。

|候选|v3参考构造|
|---|---|
|original|逐值复用v2原逻辑：在真实加减速度界内趋近期望速度；有停车要求时使用停车模板|
|brake_straight|逐值复用v2最大制动直行参考|
|brake_right|S形参考航向幅值−0.12rad|
|brake_left|S形参考航向幅值+0.12rad|
|brake_right_strong|S形参考航向幅值−0.25rad|

对后三条参考，在每个原0.2秒区间从真实后轴状态出发，设置：

```text
a = max(−max_brake, −v/Δt)
L = vΔt + 0.5aΔt²
yaw_goal = A sin(π t_next/H)
κ_request = (yaw_goal − yaw)/L，L接近0时取0
κ = 将κ_request限制到原曲率范围
steer = 将atan(wheelbase × κ)限制到原转角范围
```

随后按原常加速度、常后轴曲率定义精确积分。它不使速度瞬间归零，不预测其他目标，也不擅自改变让行、停车或目标CENTER区域。候选仍须满足全局±0.35rad航向界；每格航向带仍按参考两端外扩0.025rad，并由T2支持函数、T3硬约束和T4共同使用。

参考仅选择凸走廊和初始化T3，不是执行轨迹。T3的自行车模型、原硬约束、代价、曲率epigraph和IPOPT配置不变，仍用对应参考的状态与控制初始化。所有5候选实际处理后，只在T4通过者中选择代价最低者；失败时保留具体阶段。

## T4：有界、自适应、连续时间核验

见 [t4.py](../agentic/t4.py) 的 `_adaptive_body_interval`。仅v3启用，轨迹必须声明 `continuous_oriented_body_adaptive_v1`。

先沿用原先每段不超过0.02秒的保守核验。只有道路、目标CENTER区域、停车位置或BODY碰撞包络出现潜在几何违例时，才将该自车子段一分为二；最多递归3层，新的二分子段不小于0.0025秒。原有停车截止切分可以产生更短区间。纯STOP_DEADLINE速度违例不因它单独触发几何细分。

每个叶子区间都继续证明其**整个时间区间**，而非只检查采样点。证明依赖同一常控制运动定义和非负速度。设子段行驶弧长为L、后轴到最远车身角点距离为r，则每个中间车身点相对最近端点的运动距离不超过：

```text
BODY余量 = (1 + r|κ|) L/2 + 1e−8m
```

因此两端完整有向BODY的凸包加该余量，包含子段全部车身扫掠；中心点约束使用同类保守中心运动余量。细分减小余量，但不减小真实车身或安全要求。

**每个子段始终使用原父时间格的完整目标占用集合、全部保留不利情景、原模型总残差和1米间距。** 不按细分时间插值目标、不缩窄占用、不删除不利模式。两个闭子段覆盖原闭区间；只有所有最终叶段均被证明满足原条件才通过。预算耗尽仍存在违例就拒绝，释放前缀为0。真实碰撞、初态间距不足和未来侵入不能靠细分变成安全。

输出增加有界细分统计，独立接受器重新计算并比对。有限细分仍可能保守拒绝贴边解，不代表所有轨迹全局无解。

## 显式版本和兼容边界

- v1/v2默认路径和旧产物解释不变；v2的原走廊及原T4结果有逐值回归。
- 新走廊、轨迹分别使用 [corridor_seed_candidates_v3.schema.json](../schemas/corridor_seed_candidates_v3.schema.json) 与 [trajectory_seed_candidates_v3.schema.json](../schemas/trajectory_seed_candidates_v3.schema.json)，声明新search profile和对应核验profile。
- 原业务契约3.0.0-exp2、原wire与提示词不改；新旧数据不得只改版本标签混用。
- T3、候选编排、执行入口和独立接受器显式选择v3；接受器继续从原模型来源重建T1/T2、独立重算T4和前缀积分，不能只相信求解器成功。
- 新运行须冻结实际代码、两份派生Schema和配置；不能把离线新规划器结果追写成旧在线实验成功。

## 闭边界CENTER的补充修复

新城市frame020中，实际CENTER(0,0)位于合法target的x>=0边界，但首格±0.025rad对1.2m中心偏移取最坏支撑，误将后轴(-1.2,0)排除约0.00037498m。仅在v3、实际CENTER确实被target覆盖、original/brake_straight首段零转向且该转换排除实际初态时，将这两个参考的首格航向带收紧为[0,0]；T3/T4强制同带，后续带和S参考不变。初始yaw已固定，T3不重复加入同一初态等式；目标边界、原场景和安全标准均不改。

对于常后轴曲率κ及中心偏移d，按弧长s参数化有C(s)=R(s)+d[cosψ,sinψ]，故||C''(s)||=|κ|sqrt(1+(dκ)^2)。v3对CENTER/停车半平面使用此上界乘L²/8再加1e-8m，保守覆盖完整中心弧与端点弦的差，而非旧L/2余量。BODY扫掠/碰撞/原目标占用和自适应预算均不变；v2仍沿原路径。4545点独立曲线比较和缺中心偏移因子的反例验证数学界，不能把样例检查当任意模型证明。

## 仅用于模型修订的契约诊断

v3反馈对PREMISE_SCOPE列出声明/所需区间及实际绑定指针，区分过去对齐前提与未来情景；对PROTOTYPE_SCOPE列出模型road和domain的冲突。它不改T1 guard、前提范围、道路、占用或任何模型值，不授权规划；只要求模型依据原图和采集修订。v2原反馈格式和静态提示不变。
