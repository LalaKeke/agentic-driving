# 共享场景数据格式（1.0.0，直道参考剖面）

机器定义：`schemas/shared_scene.schema.json`。根对象是一份构造完成的米制场景；公共类型在 `definitions` 中，四份工具 Schema 通过 `$ref` 复用。所有对象禁止额外字段。Schema 检查类型与结构，工具补充检查几何、时域、版本及证据的语义关系。

## 1. 统一时空与车辆参考点

- `reference_time_s`：同一采集单调时钟中的秒数，不是 UTC，也不是模型生成时间。
- `coordinate_frame = ego_at_reference`：原点为本轮参考时刻的自车中心，横向轴向左、纵向轴向前；本剖面只使用地面二维直角坐标。
- `time_s`、`start_s`、`end_s`、`stop_deadline_s`：相对参考时刻的秒数。
- `capture_time_s`、`observed_at_s`、`valid_until_s`：采集时钟中的绝对秒数。
- 距离为米，航向为弧度，速度为米/秒，加速度为米/秒²，曲率为每米。
- 车辆参考点为自车中心，不是后轴；前后悬伸由 `front_m`、`rear_m` 表达，横向半宽由 `half_width_m` 表达。
- 初版自车初态位置、航向必须为零；轨迹只允许直线前进。新一轮观测必须重置自车坐标原点，不能直接使用上一轮坐标。

## 2. 根场景字段

所有下列字段均为必填，禁止把未知信息填成零。

| 字段 | 内容 | 约束 / 单位 |
|---|---|---|
| `metadata` | 版本、场景、来源、坐标与预测网格 | 见下表 |
| `observations[]` | 图像编号、相机编号、采集时间、图像引用 | 图像引用本身不含像素；测试采用 `fixture://` |
| `ego` | `x_m,y_m,yaw_rad,speed_mps` | 米、弧度、米/秒 |
| `vehicle` | 前后尺寸、半宽、速度/加速度/曲率边界 | 尺寸为正；由可信车辆配置提供 |
| `road_bounds` | 已知可行驶矩形 | 四个边界值，均为米 |
| `road_uncertainty_m` | 道路边界内缩量 | 非负米；来源为模型假设/实验约定 |
| `road_evidence_frame_ids[]` | 道路证据对应的图像编号 | 必须非空且引用已有图像 |
| `objects[]` | 目标状态与未来区间占用 | 可为空，但不等于系统证明没有目标 |
| `unknown_regions[]` | 模型明确标注的未知矩形区域 | T2/T4 将其作为不可通行区域；范围未知时需拒绝构造，不能填空列表掩盖 |
| `valid_until_s` | 场景覆盖的截止时刻 | 本实现为参考时刻加规划窗口，调用端仍需检查当前时钟 |

### metadata

| 字段 | 示例 / 说明 |
|---|---|
| `schema_version` | 固定 `1.0.0` |
| `scene_id` | `pedestrian_crossing_001` |
| `revision` | 非负整数；智能体修改决策或新观测时递增 |
| `reference_time_s` | 第一轮 `100.0`，停车后新一轮 `104.0` |
| `coordinate_frame` | 固定 `ego_at_reference` |
| `horizon_s`、`step_s` | 示例为 `5.0`、`0.2`；窗口必须为步长整数倍 |
| `data_origin` | `foundation_model` 或 `synthetic_fixture`；测试来源必须显式开启 |
| `model_id` | 真实适配器填写实际模型标识；测试固定为 `synthetic-not-a-model-call` |
| `calibration_id` | 标定引用；本样例为原生米制数据，不实际运行标定投影 |

跨工具必须完整匹配 metadata，不能只匹配场景编号。驾驶决策另外携带场景编号与修订号。

## 3. 目标与占用

每个目标包含：`id`、`evidence_frame_ids[]`、`position`、`velocity_mps`、`position_uncertainty_m`、`occupancy_intervals[]`。

```json
{
  "start_s": 0.0,
  "end_s": 0.2,
  "bounds": {
    "xmin_m": 17.6, "xmax_m": 18.4,
    "ymin_m": -3.35, "ymax_m": -2.35
  }
}
```

`bounds` 不是时刻点，而是**模型声称覆盖整个时间区间内目标车身的矩形**，尚未加位置不确定性、安全间距或自车尺寸。工具不从目标速度另行生成未来占用。模型若只能给出离散点而无法给出区间覆盖依据，则不能直接满足本接口。

每个目标必须恰好提供一个预测网格区间的完整列表，按时序无缺口覆盖整个窗口。位置不确定性解释为二维各方向独立的绝对膨胀界，不是标准差、概率或置信度。T2 与 T4 各自从原始占用重新构造边界；二者不是串行重复膨胀。

当前仅允许一个明确的占用包络。多个模型假设须由可信适配器以保守并集包络表达；该步骤只能整合已有假设，不能引入新的目标预测。包络覆盖性仍属于 G2 待验证内容。

## 4. 驾驶决策

字段：`scene_id, revision, behavior, desired_speed_mps, lane_center_y_m, max_lateral_deviation_m, yield_to, stop_before_x_m, stop_deadline_s, valid_until_s`。

- `stop_yield`：停车上界为**自车中心位置**，截止时刻为相对秒；二者必须给出数值。
- `resume`：恢复行驶；停车上界与截止时刻必须为 `null`，不能沿用旧停车要求。
- `hold_lane`：契约预留的行为，参考工具明确返回 `UNSUPPORTED_BEHAVIOR`，不静默执行。
- `desired_speed_mps` 是优化偏好，不是可突破运动约束的理由。让行、停车边界、截止时刻与允许车道为硬要求。
- `yield_to` 引用场景目标编号，不允许引用不存在的对象。

## 5. 公共消息与失败语义

请求固定为 `kind=request, tool, request_id, payload`；响应固定为 `kind=response, tool, request_id, status`。

- `status=ok`：具备合法工具输出，放在 `payload`。
- `status=error`：输入错误、时空不一致或工具无法产生结果，放在 `error.code/message/details`。
- **T4 的核验不通过不是协议错误**：仍为 `status=ok`，但 `verification.verdict=FAIL`，执行前缀为零。
- `NO_FEASIBLE_TRAJECTORY` 仅表示本候选集合无可行解，不是一般规划问题不可行证明。

同一模型假设可能存在错误；协议结构正确与核验通过都不构成真实环境准确性或安全性的证明。离线真值不属于场景字段，不能送入运行时工具链。
