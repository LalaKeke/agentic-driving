## 必要信息缺失与软件拒绝的区分

**确实没有在接口中提供的信息：** 147 条未来占用、11 份尺度/道路、117 项有限不确定范围以及部分交通适用条件。即使绕过首个 guard，剩余值也不能证明任务域五秒覆盖。原文字多次保留启动、转向、遮挡进入等未知；工具不能生成他车预测或将 null 转为空占用。这只能证明当前输出不足，不能断言基座模型原则上不可能估计。

**相关性判定的实际实现：** 冻结 `t1.py:25,47–58` 使用全局门槛并要求所有声明对象完整；没有计算对象未来集合与任务可达域的相交，也没有候选走廊作为输入。它是保守的全场景充分条件，尚不能据此证明存在算法循环。没有可靠未来界时，目前也无法证明某个被列出的未知与任务无关。任意距离阈值、当前遮挡源区分离或只选一个安全候选都不足以删除未知。

**表达限制：**

1. 有界占用可表达；多个 `alternatives_m` 均由工具保留。条件前提却只在自由文本，缺对象/情景/区间绑定；逐段联合可能包含额外模式切换，更保守。`occupancy=null` 不能区分“未给覆盖”和“无法给有限界”；全局 unknown 没有对应对象和时间域。
2. `reference_time_id` 表达状态参考，`time_ids` 表达采集证据；T1 另要求每对象引用精确参考时刻，使只出现在异步侧后图像的目标，即使模型说明对齐仍拒绝。真实 25 份响应中有 84 条此类潜在引用；83 条同时缺占用，只有 1 条已有 25 段，相差约 7.616ms。不能宣称删除时间 guard 后这些响应能通过，也不能向证据添加没看见该目标的前向图像。
3. Schema 允许一个真正整五秒包络，T1/提示词要求 25 段。人工相同集合等值细化后通过，说明网格表达限制。本轮 23 条非空包络已经正确分段，因此它不是这 27 次首拒的实测原因；旧占位矩形也不能靠切分获得依据。

[完整相关性审查](relevance/RELEVANCE_AUDIT.md) 和 [84 条真实时间引用](relevance/real27_async_evidence.json) 保留具体代码与原文。15 个独立人工反例包括远处快速入侵、遮挡源区外未来侵入、合理不利分支碰撞、异步已对齐状态、粗包络与缺段/null；[显式加载冻结 T1 的复跑](relevance/replay/replay.json) 全部通过。它们是软件语义证据，在线分子和分母均不增加。
