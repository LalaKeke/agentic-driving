# 流程失败诊断与修复

本轮针对“真实图像→真实模型→T1→T2→T3→T4→消费短前缀”的完整成功标准进行修复。**软件测试通过、模型返回 JSON、人工轨迹通过均不等于真实物理链路成功。** 原失败记录、案例图和协议保持原样。

## 已确认的问题与实际改动

1. **目标区域语义冲突**：10 份真实响应的目标框按原 T2 规则内缩后全部为空。新版本提示 `driving_v2_2` 明确它是全时域允许 CENTER 区域，停车点用 stop 表达，不能凭空扩大道路。
2. **有效期与前缀混淆**：6/10 响应只覆盖 0.2s，工具要求 5s。适配器显式传入由采集记录推导的规划截止、前缀和网格，不让模型猜接口要求。
3. **占用格式不明确**：54 条非空目标占用全都只有一段，旧工具要求 25 段；新提示明确每段完整覆盖，未知仍为 null，未对旧占位矩形做“切分后认定有效”。
4. **尺度标签与实际支持不一致**：8/10 输出使用当前剖面不支持的 calibrated_ground_plane。新提示明确限制；不改变标签来掩盖缺少尺度依据。
5. **首个错误遮住其他错误**：反馈附加纯契约诊断，指出有效期、目标初态与占用网格等问题；不修改模型数据，不授权规划。
6. **固定走廊锚点误拒**：旧 T2 要求每个未来单元都包含最初后轴位置。新增显式 moving_seed 策略，以自车状态/限制/语义模板生成零转向参考，不预测他车；保留相同车身包络、安全间距、原目标占用、T3/T4约束，检查首态和相邻走廊连通。默认 initial_anchor 保持兼容。seed失败不能称全局物理无解。
7. **额外数值收缩误拒停车边界**：T3 对接口声明的闭半平面另加一微米收缩，导致合法静止边界无解。去掉该未声明收缩，T2物理安全间距和独立T4完全保留。
8. **评价采样阻塞规划**：原批处理必须先成功做 G2 采样再规划。现改为规划优先，`--repeats 0` 可直接规划，评价调用可选且放在后面；每轮智能体始终参与。
9. **过程结束误当成功**：新增独立接受器，重建 T1/T2、从原场景重新核验 T4、校验图片和全部摘要、执行回执及前缀积分。分别标注在线/人工、MOVING_PREFIX/STATIONARY_HOLD、单窗口/多轮、GT未评价。规划失败的 online CLI / 批处理退出 3，不再以退出 0暗示成功。
10. **尝试统计不完整**：模型与工具开始/结束/失败、次数、阶段和耗时逐项记录。传输超时不重复当作语义修订；配置/模型服务不可用单独停止。源日志补充 launcher/config/capture哈希。

[只读原响应审计](contract_audit.md) / [逐条机器审计](contract_audit.json)。旧字段、旧提示词与旧模型输出 Schema 原字节保留；新提示词仍使用输出契约2.1，不能与原2.0或旧2.1提示结果混作同一实验。

## 验证与严格复测

工程回归包含实际CasADi/IPOPT与独立T4：固定锚点误拒场景在moving_seed下求解并核验通过；真正初态碰撞/未来撞静止自车仍拒绝；合法停车边界可以求解。它们都是明确标注的人工软件测试，不能计入真实模型分子。
