# 流程失败诊断与修复

本轮针对“真实图像→真实模型→T1→T2→T3→T4→消费短前缀”的完整成功标准进行修复。**软件测试通过、模型返回 JSON、人工轨迹通过均不等于真实物理链路成功。** 原失败记录、案例图和协议保持原样。

## 已确认的问题与实际改动

1. **目标区域语义冲突**：10 份真实响应的目标框按原 T2 规则内缩后全部为空。新版本提示 `driving_v2_2` 明确它是全时域允许 CENTER 区域，停车点用 stop 表达，不能凭空扩大道路。
2. **有效期与前缀混淆**：6/10 响应只覆盖 0.2s，工具要求 5s。适配器显式传入由采集记录推导的规划截止、前缀和网格，不让模型猜接口要求。
3. **占用格式不明确**：54 条非空目标占用全都只有一段，旧工具要求 25 段；新提示明确每段完整覆盖，未知仍为 null，未对旧占位矩形做“切分后认定有效”。
4. **尺度标签与实际支持不一致**：8/10 输出使用当前剖面不支持的 calibrated_ground_plane。新提示明确限制；不改变标签来掩盖缺少尺度依据。
5. **首个错误遮住其他错误**：反馈附加纯契约诊断，指出有效期、目标初态与占用网格等问题；不修改模型数据，不授权规划。
6. **固定走廊锚点误拒**：旧 T2 要求每个未来单元都包含最初后轴位置。新增显式 moving_seed 策略，以自车状态/限制/语义模板生成零转向参考，不预测他车；保留相同车身包络、安全间距、原目标占用、T3/T4约束，检查首态和相邻走廊连通。默认 initial_anchor 保持兼容。seed失败不能称全局物理无解。
7. **额外数值收缩误拒停车边界**：T3 对接口声明的闭半平面另加一微米收缩，导致合法静止边界无解。去掉该未声明收缩，T2物理安全间距和独立T4完全保留。
8. **评价采样阻塞规划**：原批处理必须先成功做 G2 采样再规划。现改为规划优先，`--repeats 0` 可直接规划，评价调用可选且放在后面；每轮智能体始终参与。
9. **过程结束误当成功**：新增独立接受器，重建 T1/T2、从原场景重新核验 T4、校验图片和全部摘要、执行回执及前缀积分。分别标注在线/人工、MOVING_PREFIX/STATIONARY_HOLD、单窗口/多轮、GT未评价。规划失败的 online CLI / 批处理退出 3，不再以退出 0暗示成功。
10. **尝试统计不完整**：模型与工具开始/结束/失败、次数、阶段和耗时逐项记录。传输超时不重复当作语义修订；配置/模型服务不可用单独停止。源日志补充 launcher/config/capture哈希。

[只读原响应审计](contract_audit.md) / [逐条机器审计](contract_audit.json)。旧字段、旧提示词与旧模型输出 Schema 原字节保留；新提示词仍使用输出契约2.1，不能与原2.0或旧2.1提示结果混作同一实验。

## 验证与严格复测

工程回归包含实际CasADi/IPOPT与独立T4：固定锚点误拒场景在moving_seed下求解并核验通过；真正初态碰撞/未来撞静止自车仍拒绝；合法停车边界可以求解。它们都是明确标注的人工软件测试，不能计入真实模型分子。

## 条件估计提示词的独立实验

新增 driving_v2_3，输出仍2.1、物理约束不变。明确区分可信采集记录、基座可证伪的条件场景假设、条件核验结论；未来占用不要求未来真值已经观察。允许有依据并写明前提的米制估计、有限范围和多个预测情景，但禁止为通过而填数字、删除合理不利情景、换尺度标签掩盖缺依据或将范围当校准保证。未知仍可为null，G2仍独立评价。此实验不改写2.2失败、不把假设当真实世界安全证明。

原四窗配置为 `conditional_estimation_config.json`；两个探索窗同样例另组；开始前冻结源码。新增聚合诊断可报告退化几何；launcher归档明确固定开始提交而非结束时HEAD。单因素因果改善不作预设，只有实测完毕才记录成功率。


## 最终实际结果

**本轮完成工程修复和真实复测，但未观察到真实全链成功，不能宣称成功率已提高。** [机器汇总](final_summary.json) 保留全部分组、尝试、服务失败与严格接受结果。

| 实验组 | 窗口 | 模型尝试 / 有效结构化响应 | 在线严格成功 |
|---|---:|---:|---:|
| driving_v2_2 原四窗 | 4 | 8 / 8 | 0/4 |
| driving_v2_2 探索两窗 | 2 | 4 / 4 | 0/2 |
| driving_v2_3 原四窗 | 4 | 8 / 7 | 0/4 |

### 哪些改善已测到，哪些没有

- 有效期覆盖5s、避免受拒校准标签等机械要求已改善。不能把occupancy=null当作网格正确，也不能把退化target多边形当作有效全时域区域。
- 条件估计提示已让模型给出更多原生米制值和若干25段整区间预测，但仍保留相关启停/转向/遮挡侵入未知；其自报范围不具备经校准的可靠性保证。
- 原输入仅前向5帧、每侧后相机1帧。增强组改为前向5帧、其余五相机各3帧，共20张原始图像，全部在原两秒历史内。只读取采集/自车/标定五张允许表，没有检测/跟踪/预测模型、注释或地图输入。模型开始给出部分侧后车辆的当前静止估计，但未补齐五秒占用，**不是端到端成功率提高**。
- 未来占用和相关未知仍是实测阻塞项。车身外接圆及CENTER各向转换也可能误拒窄路，但本轮真实分支根本未到T2，不能伪称它们是这些真实失败的实际原因。暂未用新箱形剖面掩盖上游缺失。

### 最后合入的 T3 修复及软件证据

用严格曲率弦差界替换L/2充分条件，未修改T4、安全间距或环境假设。见 [数学说明](../../docs/T3_CURVATURE_BOUND.md) 与 [合并前真实IPOPT对照](chord_premerge_tests.txt)：原窄目标反例求解不可行，修复后末位置约30m、原T4 PASS。实际曲线5025个独立积分点、15075次数学界比较及碰撞拒绝均通过。旧T4仍可能保守拒绝贴边解，此项不冒称消除了所有规划限制。真实模型试验均发生在此T3修改前，不能归因其在线效果。

最终 [139项测试](final_tests.txt) 全部通过、0跳过，15.791s；[完整人工闭环](delivery_demo.txt) 实际完成26轮、27次脚本智能体调用、停稳后恢复约2m/s。逐轮软件接受与模拟前缀证据在 delivery_demo_evidence；该人工验证在源码有未提交改动时运行，实际manifest保留code_dirty=true及逐源SHA，不伪称干净提交实验，不计入在线成功。
