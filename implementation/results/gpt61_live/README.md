# GPT-6.1 真实 nuScenes 试验与 G2 初步结果

**结论：ChatGPT 会员登录、GPT-6.1 多帧图像输入和结构化语义输出已经跑通；当前输出没有支撑可核验物理轨迹，完整端到端可行性未验证通过。** G2 已使用真实模型输出做部分评价，但没有预先认可的通过阈值，因此不作 G2 通过结论。所有数据均为本服务器实际运行所得，不使用人工测试替身代替在线模型。

本次运行跨越 2026-10-27 深夜至 2026-10-28 凌晨（Asia/Shanghai）。原始开始时间和各阶段时间保存在 raw_runs 与 client 中，JSON 使用 UTC。机器摘要见 [summary.json](summary.json)。

## 会员路径与工程修复

用户提供的有效代理为 `http://127.0.0.1:17891`；原执行环境错误指向 17890。代理只作用于测试子进程，没有新建 SSH 转发、修改全局代理或改动其他项目环境。首页返回 Cloudflare 403 challenge，但这不等于 Codex 模型接口不可用。

系统 CLI 0.147.0 经该代理收到服务端 400 / model_not_found，提示 gpt-6.1-sol 不支持当前 ChatGPT 路径。随后在本项目 `runs/tools/codex-0.164.0` 独立安装官方 CLI 0.164.0，同一登录态和同一模型成功返回 JSON，并完成真实图像调用。系统全局 CLI 未替换。客户端包锁和安装入口在 experiments/nuscenes 中，二进制 SHA256 见 [client/installed_cli_fingerprints.json](client/installed_cli_fingerprints.json)。

登录状态为 ChatGPT；子进程移除 API Key 环境变量、强制 ChatGPT 登录、忽略自定义 provider 配置。没有读取或提交会员令牌，没有 API Key 回退。模型请求固定为 `gpt-6.1-sol`，不换模型。服务端未暴露权重 snapshot，provenance 如实记录其身份依据是显式 CLI 请求。

模型在仓库外的临时目录运行，只接收原始图像、采集元数据、自车状态、车辆配置和通用导航意图。禁用 shell、搜索、插件、其他代理和文件访问工具；所有成功响应的工具调用数为 0。新版 CLI 的“code-mode host 已禁用”启动诊断被精确识别，其他错误及任何工具调用仍拒绝。离线 GT、地图和标注投影图从未作为模型输入。

## 原协议 2.0：四例实际尝试

每例 10 张真实图像，合计 40 张不同图像；重复调用使用相同观测，不算新增独立样本。历史窗口至多 2s，预测窗口 5s、网格 0.2s。车辆尺寸、轴距和中心偏移为显式研究假设，不是 nuScenes 车身实测值。

| 样例 | 有效响应 | 原协议观察结果 | 执行分支 |
|---|---:|---|---|
| 白天行人横穿 scene-0553 | 4 | 停车让行；包含两次失败反馈修订，仍有无界未知 | T1 三次 UNBOUNDED_UNKNOWN；无轨迹 |
| 施工障碍/左弯 scene-0061 | 3 | 减速停车；识别让行标志和施工遮挡；首次另有 300s 超时 | 续跑后 T1 两次 UNBOUNDED_UNKNOWN；无轨迹 |
| 路口横向车流 scene-0757 | 2 | 红灯保持停车；米制位置和速度未给出；一次反馈请求 600s 超时 | T1 一次 MISSING_SCALE；无轨迹 |
| 夜间行人 scene-1100 | 0 | 原协议请求在 600s 内未完成 | T1–T4 未运行，保留为失败尝试 |

原协议共 **9 份有效响应**：6 次无反馈的原始调用（3 个窗口各 2 次）和 3 次带反馈修订。它们不是 9 个独立场景。原始 T1 运行共拒绝 6 次：5 次 UNBOUNDED_UNKNOWN、1 次 MISSING_SCALE；真实模型输出上 **T2/T3/T4 调用均为 0，已释放前缀为 0**。不能将软件测试中的人工轨迹通过率挪作真实模型规划通过率。

共有三次完成前超时：施工初次 300s、路口反馈修订 600s、夜间初次 600s。首次批处理错误地将单例超时传播成全局不可用，已修复；未执行的项有独立状态，不计为已调用。随后只续跑未完成三个样例，单次时限改为 600s、最多一次修订；已完成的白天例未重跑。所有旧失败原样保留。超时不被解释为模型视觉预测错误，未完成请求的 token/会员额度消耗不可见。

## 单独的 2.1 格式复核

真实响应暴露出 2.0 的矛盾：occupancy 被强制为非空数组，但模型文字承认没有可靠的整区间预测，有时将结构中的矩形直接称为 unsupported placeholders。不能把这些结构标签当作已支持的未来占用。

新增**显式模型输出契约 2.1.0**，允许 `occupancy:null`；原 Schema 与提示词保留原字节，原四例条件未改。仅对同一夜间窗口做一次独立格式复核，实际约 42.84s 返回：5 个目标均 occupancy=null，位置/速度/不确定界限也未知，road=null、scale_basis=unknown、unbounded_unknown=true。本地 T1 复核返回 MISSING_SCALE，不产生执行轨迹。

该复核证明未知可以忠实编码，不证明米制 grounding 或五秒预测可行。它与原协议分开保存、分开评价，不用来改写原协议夜间超时或宣称成功率 4/4。原协议 9 份响应加此复核 1 份，共 **10 份真实图像场景响应**；另有 1 次仅文本连通性成功，不计入 G2 场景数据。

契约说明与迁移见 [模型输出契约2.1](../../docs/模型输出契约2_1.md)。实测后还补充了 T1 的校准前提硬化：当前原生米制剖面不能仅凭相机内外参和 calibrated_ground_plane 标签宣称尺度已验证；没有可信平面/像素投影契约时返回 CALIBRATED_PROJECTION_UNVERIFIED。该后续硬化不重写原运行中的失败原因。

## G2：可评价性与初步数值

GT、地图、未来标注和审阅对应关系只在离线评价读取。原协议只取 6 份**无条件**响应用于重复性，带失败反馈的修订不混作相同提示词的重复调用。夜间 2.1 单例另算；评价器拒绝静默混合契约版本。

在原协议 6 份无条件响应的 39 条目标条目中，9 条有点位，**0 条有米制速度**，1 条有数值不确定界限；重复调用会重复计数，这不是检出率。六份响应均标记无界未知。完整场景没有达到当前工具输入契约。

预选焦点目标的定位评分不足：重叠人物和合并施工对象没有唯一对应时不按最小误差硬配；路口和夜间对应目标的位置仍为 null。具体审阅和原始图像投影保存在 offline_review，审阅人为助手辅助视觉审阅，非独立人工盲审。

另外对两个可唯一辨认的目标作**探索性核对**，在看到输出后选择，仅作诊断，不是预注册验证集：

| 可核对目标 | GT 距离 | 两次点位误差 | 两次点位标准差 (x,y) |
|---|---:|---|---|
| 白天远左侧行人 | 9.839m | 0.2246m、0.1515m | (0.15m, 0.10m) |
| 施工例前方白色 MPV | 14.085m | 3.9798m、3.0112m | (0.50m, 0.00m) |

点位以 GT 框中心的地面投影为参考；模型目标参考点语义仍需更严格约定，不能将这些数字作为无条件定位精度。第二次 MPV 的点位差 3.011m 大于所报 2.5m 范围，至少不能把该自报范围直接视为已校准误差界。仅两目标、每目标两次，不能外推到距离/遮挡分层的总体性能。

未来占用必须区分原始几何重合与有效预测：模型明确否认有效性的一个巨大占位包络，原始区间面积重合值为 **1.0**，但平均面积约为 GT 区间包络的 **98.39 倍**。原始值完整保留；经明确的模型自述无效标记后，不计为可用预测。它不是 100% 安全概率或可靠覆盖。速度误差和可支持的完整未来覆盖没有可用得分，记 null，而不是默认零误差。占位审阅前的原始计算也保留，便于复核。

已计算道路边界/面积诊断，但模型只给小范围已知补丁，地图是更大的静态 drivable_area：边界 Hausdorff 会主要反映范围不一致，不能将约 28–42m 的差异直接称为车道定位误差。地图与施工临时可通行区域也非完全同义。距离、可见比例和场景分组已保留；当前可评分点主要为近距离、高可见比例，未覆盖远距/强遮挡统计。没有认可的验收阈值，**G2 不判通过**。

三份 raw_runs 保存实际输入、结构化输出、来源/图像 SHA256、usage、工具失败反馈和代码信息。前两次运行的 27 个核心源码/Schema/提示词文件是在事后从 Git 与确定性补丁复原，**逐个与当时已保存的 SHA256 完全匹配**，不是伪称当时已保存完整源码快照；其 source_reconstruction.json 和 ZIP 一并保留。格式复核由干净提交 1f69d61 启动，29 个对应文件从该提交归档并逐个核对。原 RunLog 的源哈希范围不覆盖 launcher，不能称全文件系统来源审计。评价器来源版本/哈希另存 summary.json。

GT 未来区间来自约 2Hz 标注的线性中心插值与车身外接包络，只覆盖这套插值代理，不能当作测得的连续时间真值。采集与标注约 34–37ms 偏差已在离线对齐。车辆尺寸和中心偏移为研究假设；没有已核实的地面平面/像素接地点证据。样例是人工筛选的公开 mini 窗口，可能存在预训练曝光、未来完整轨迹筛选偏差、语义对应关系和参考点误差，不能称独立未见测试或部署安全证明。

本次没有操作真实车辆，没有注入离线 GT 帮模型修订，没有降低安全间距、改预测窗口或放松物理硬约束来取得通过。原协议 5s / 0.2s 保持。当前最直接的研究缺口是可支持的尺度、完整场景及未来占用/不确定界限，而不是“优化器已成功所以安全”。真实模型输出上的 T2–T4 与成功执行分支仍未验证。

## 复现

本机现有环境可直接运行；其他环境先准备原始数据并安装项目依赖。使用你已配置的 17891 代理，以下命令不需要 API Key，也不会修改全局 CLI：

```bash
cd /data2/hzy/MAP/agentic-driving
# 仅首次需要：按锁定包安装项目内官方客户端
.venv/bin/python implementation/experiments/nuscenes/install_codex_client.py

# 重新采样属于新试验，模型结果不保证逐字复现
DRIVING_CODEX_TIMEOUT_S=600 DRIVING_OUTPUT_CONTRACT=2.0.0 \
  .venv/bin/python implementation/experiments/nuscenes/run_cases.py \
  --index runs/nuscenes_cases_20261027/runtime_index.json --runs runs \
  --repeats 1 --max-revisions 1 --backend codex_cli --model gpt-6.1-sol

# 不调用模型，纯离线复算本次探索性 G2 结果
cd implementation
../.venv/bin/python -m agentic.cli g2 \
  --records results/gpt61_live/g2/g2_original_contract/records/*.json \
  --truth results/gpt61_live/g2/g2_auxiliary_reviewed_truth.json \
  --config examples/v2/g2_config.json --out /tmp/gpt61-auxiliary-recomputed.json
```
